# 参考视频技术对照与本项目落地方案

## 参考视频中确认到的技术

视频说明的 ZYNQ 灵巧手方案使用 OV5640 采集，并在 PL 端完成 RGB 转 YCbCr、中值滤波、Cb/Cr 肤色检测、腐蚀、八连通处理、膨胀、Sobel 边缘和特征值计算；PS 端配置摄像头、把识别结果映射到 Arduino/机械手。视频链路还使用 VDMA 将图像存入 DDR，并通过 UDP 把结果送到电脑显示。

本项目的目标不是控制机械手，而是“手语动作 -> 中文文本 -> 语音播报”。因此应复用视频方案的异构计算思路，而不是逐项照搬所有图像算子。

## 对照关系

| 参考视频 | 本项目实现 | 当前状态 |
|---|---|---|
| OV5640 视频采集 | PYNQ-Z2 上的 USB 摄像头，由 PS/OpenCV 采集 | 代码已备；需重新上板确认设备节点和帧率 |
| RGB -> YCbCr | HLS `rgb_to_ycrcb` 整数流水线 | 已有源码、IP 和 overlay |
| Cb/Cr 肤色阈值 | AXI-Lite 可配置 Y/Cr/Cb 阈值 | 已有源码；需用真实光照标定 |
| 中值/腐蚀/膨胀 | 当前 HLS 为 3x3 多数滤波，PS 端再做连通域/ROI 归一化 | 已实现等价去噪目标；CPU/PL 一致性待上板 |
| 八连通域 | PS 端 OpenCV 最大连通区域/轮廓 | 已实现；暂不迁入 PL，降低硬件复杂度 |
| Sobel/静态特征 | HOG + 形状/运动序列特征 | 已实现；Sobel 不是当前模型契约，不应无依据添加 |
| 最小二乘分类 | RandomForest/线性模型的 NumPy 板端推理 | 已实现，现有离线指标需用独立数据复核 |
| VDMA -> DDR | AXI DMA -> HLS -> AXI DMA | 软件接口已有；整帧受 16383 字节限制，尚未完成硬件验收 |
| UDP 电脑显示 | 原子 JSON/JPEG + SCP 轮询 | 已实现；局域网演示足够，后续可按性能需要换 WebSocket/UDP |
| Arduino/机械手映射 | 稳定动作事件 -> 中文 WAV/Windows TTS | 本轮增加唯一事件号、稳定确认和释放再触发 |

## 推荐的最终架构

```text
USB 摄像头
  -> PS/OpenCV 取帧
  -> AXI DMA 分块送入 PL
  -> PL: RGB->YCrCb + 肤色阈值 + 3x3 去噪
  -> PS: 最大连通域 + 128x128 ROI + HOG/运动特征
  -> PS: NumPy RandomForest 动态分类
  -> 连续窗口稳定确认 + unknown 释放
  -> 原子 JSON/JPEG（唯一 event.id）
  -> PC 或板端 WAV/TTS 语音播报
```

PYNQ-Z2 的 Zynq-7020 资源有限，先把像素级、规则固定、并行度高的预处理放 PL，把可迭代的分类和时序决策留在 PS，是更稳妥的软硬件划分。当前阶段不建议将完整随机森林、HOG、连通域或语音合成强行搬进 PL。

## 无板卡阶段的完成边界

已能验证：模型文件可加载、动态特征和分类接口、稳定事件门控、JSON 协议、PC 去重播报、展示画面组合、HLS C 仿真已有工程。
