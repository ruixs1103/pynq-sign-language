**竞赛名称：** 2025年全国大学生嵌入式芯片与系统设计竞赛——FPGA创新设计大赛 AMD赛道
**赛道类型：** 自主选题 - 初级赛道

**提交日期：** 2026-10-31

---

## 摘要

针对听障或语言障碍人群与非手语使用者之间的交流障碍，本项目设计了一套基于 PYNQ-Z2 的静态手语识别与语音播报系统。系统以 Logitech C270 USB 摄像头采集 640×480 彩色图像，采用 Zynq PS/PL 协同架构：PL 端 HLS IP 通过 AXI DMA 接收像素流，流水完成 BGR 到 YCrCb 的定点转换、肤色阈值分割以及 5×5 开闭形态学处理；PS 端完成最大轮廓提取、几何特征计算、模板分类、稳定确认、产品界面和浏览器 WAV 语音播报。系统可识别数字 1～5、点赞和停止共 7 类静态手势，并同时展示真实手部图像、PL 二值处理图和文字结果。最终板级测试中，全部静态类别、文字和语音均正常，PL 分割链路得到确认，连续运行 5 分钟未出现明显卡顿、崩溃或功能异常。项目验证了在低成本异构 SoC 上以可解释、轻量化方法实现手语辅助交互的可行性，并保留了进一步扩展动态手势与更多 PL 加速模块的接口。

**关键词：** PYNQ-Z2；手语识别；HLS；PS/PL 协同；语音播报

## 1. 项目概述

### 1.1 选题背景与意义

手语是听障人群的重要交流方式，但普通交流者通常没有接受系统手语训练。依赖云端的大模型方案可能受到网络、成本和隐私限制。本项目使用 PYNQ-Z2 在本地完成图像处理与识别，将结果直接转换为文字和语音，为低成本、离线、可解释的辅助交流终端提供原型，同时体现 FPGA 在规则化像素运算中的流水并行优势。

### 1.2 项目目标

**功能目标：**

- 从 USB 摄像头实时采集手部画面，识别数字 1～5、点赞和停止 7 类静态手势。
- 同屏显示真实图像、PL 处理后二值图和识别文字，并播放对应中文语音。
- 使用 PL 加速肤色分割和形态学预处理，保持 PS 端分类与界面的可迭代性。
- 提供可重复部署的 Notebook/Voilà 产品入口，不覆盖板端原有工程。

**学习目标：**

- 掌握 HLS 流水化、DATAFLOW、AXI4-Stream、AXI4-Lite 和 AXI DMA 的设计与调试。
- 掌握 Zynq PS/PL 软硬件划分、Overlay 驱动、板级验证和产品化展示流程。

### 1.3 技术规格

- **目标器件：** AMD/Xilinx Zynq-7000 XC7Z020-CLG400-1（PYNQ-Z2）
- **开发环境：** Vivado 2026.1、Vitis HLS 2026.1、PYNQ 3.1.1
- **编程语言：** HLS C++、Python
- **验证平台：** Vitis HLS C 仿真/协同仿真、Vivado 实现、PYNQ-Z2 板级验证
- **应用领域：** 边缘视觉、辅助交流、人机交互

## 2. 需求分析与系统设计

### 2.1 功能需求分析

**核心功能模块：**

1. **图像采集模块：** 通过 C270 获取 640×480 BGR 帧，并进行受限强度的软件白平衡。
2. **PL 预处理模块：** 完成颜色空间转换、肤色阈值和 5×5 开闭运算，输出 0/255 二值 mask。
3. **识别与交互模块：** 提取轮廓与指尖/几何特征，模板分类后稳定确认，显示并播报结果。

**性能需求：**

- 工作频率：HLS 目标 100 MHz，估算可达约 135.2 MHz；系统按 100 MHz 约束设计。
- 数据吞吐率：像素主循环目标 II=1；端到端吞吐受 USB 摄像头、DMA 和浏览器显示共同限制。
- 延迟要求：满足现场交互演示；最终界面 FPS 和端到端延迟尚未由界面记录，标记为 `TBD-TEST`。
- 精度要求：7 类正式演示应正确识别；逐类重复准确率和未知动作召回率标记为 `TBD-TEST`。

### 2.2 系统架构设计

#### 2.2.1 顶层架构

```text
Logitech C270 USB Camera
          |
          v
 PS/OpenCV capture -> input buffer -> AXI DMA MM2S
                                          |
                                          v
                    +----------------------------------+
                    | PL: skin_morph HLS IP            |
                    | BGR->YCrCb -> threshold          |
                    | -> erode -> dilate -> dilate     |
                    | -> erode                         |
                    +----------------------------------+
                                          |
                                          v
 PS contour/features <- output buffer <- AXI DMA S2MM
          |
          +-> template classifier -> stability filter
          +-> live image + binary mask + text
          +-> browser WAV speech
```

#### 2.2.2 状态机设计

HLS 顶层由 `ap_ctrl_hs` 控制，板端产品控制采用等价的软件状态流程：

```text
  INIT -> CAPTURE -> PL_PROCESS -> CLASSIFY -> STABILIZE -> DISPLAY
    ^                                                        |
    |---------------------- next frame -----------------------|
                              |
                           STOP/ERROR
```

**状态说明：**

- INIT：加载 bit/hwh、检查 `skin_morph_0` 和 `axi_dma_0`、配置寄存器并打开摄像头。
- CAPTURE：获取一帧，完成尺寸检查和轻量白平衡。
- PL_PROCESS：刷新缓存，按 S2MM 后 MM2S 的安全顺序启动 DMA，等待完成或超时。
- CLASSIFY：提取最大轮廓和 24 维特征并进行阈值模板匹配。
- STABILIZE：连续结果满足稳定条件后才触发语音，避免抖动和重复播报。
- DISPLAY：更新真实图、二值图和文字；随后进入下一帧。
- STOP/ERROR：释放摄像头及 UI 资源，错误时保留诊断信息。

#### 2.2.3 时序设计

HLS 时钟目标为 10 ns。颜色转换和形态学内部循环采用 PIPELINE，顶层使用 DATAFLOW 将颜色转换、四级形态学和流输出重叠执行。行缓冲避免保存多幅完整中间图。AXI DMA 负责 PS DDR 与 PL 流接口之间的数据搬运，输入输出缓存显式执行 cache flush/invalidate。HLS 估算时钟为 7.396 ns；完整 Vivado post-route WNS/TNS 仍需从最终实现报告提取。

### 2.3 接口设计

**输入接口规格：**

- AXI4-Stream 位宽 32 bit，每个字低 24 bit 按 B、G、R 携带一个像素。
- AXI-Lite 参数：`rows`、`cols`、`cr_lo`、`cr_hi`、`cb_lo`、`cb_hi`。
- 控制：`ap_start/ap_done/ap_idle/ap_ready`，DMA MM2S/S2MM 状态。

**输出接口规格：**

- AXI4-Stream 位宽 32 bit，低 8 bit 输出 0 或 255 的 mask。
- 每行末尾产生 TLAST，PS 端重建 640×480 二值图。
- 产品状态通过页面文字、图像、停止按钮和浏览器音频反馈。

## 3. 详细设计与实现

### 3.1 核心算法设计

PL 采用定点近似完成颜色转换：

```text
Cr = 128 + (128R - 107G - 21B) / 256
Cb = 128 + (-43R - 85G + 128B) / 256
mask = 255, if cr_lo<=Cr<=cr_hi and cb_lo<=Cb<=cb_hi; else 0
```

二值图依次执行 5×5 腐蚀、膨胀、膨胀、腐蚀，对应开运算后闭运算。PS 选择最大有效轮廓，构造面积、周长、外接矩形、凸包、凸缺陷和指尖等 24 维归一化特征，与 `sign_templates.json` 的类别模板计算距离；超过类别阈值则输出未知。

**硬件实现策略：** 每像素颜色转换与阈值判断流水化；形态学使用行缓冲和固定邻域核；多阶段通过 `hls::stream` 与 DATAFLOW 连接，目标 II=1。分支丰富的轮廓和分类逻辑保留在 ARM PS，降低硬件接口复杂度。

### 3.2 关键模块设计

#### 3.2.1 `skin_morph` HLS IP

**功能描述：** 接收 BGR 像素流，输出经肤色分割与形态学净化的二值流。

**接口定义（简化）：**

```cpp
void skin_morph(
    hls::stream<axis32_t>& src,
    hls::stream<axis32_t>& dst,
    int rows, int cols,
    int cr_lo, int cr_hi,
    int cb_lo, int cb_hi);
```

**逻辑设计：** `bgr_to_mask`、四个 `morph_stage` 和 `mask_to_axis` 在 DATAFLOW 区域并行；输出保持 AXI 流控制字段，便于 DMA 接收。

#### 3.2.2 PS Overlay 与产品模块

**功能描述：** `pl_hand_seg.py` 管理 Overlay、寄存器和 DMA；`pynq_sign_language.py` 完成轮廓特征与模板分类；`board_static_demo.py` 管理循环和稳定确认；`product_display.py` 构建独立大画面；`board_voice.py` 播放离线 WAV。

**逻辑设计：** bit/hwh 必须成对加载；DMA 采用接收通道优先启动并设置超时；同一稳定动作只播报一次，动作释放后才能再次触发。

### 3.3 资源使用设计

**逻辑资源规划：**

- LUT/FF：颜色计算、阈值比较、流控制和行缓冲地址逻辑。
- DSP：定点乘加颜色转换；HLS 估算使用 25 个 DSP。
- 时钟：HLS IP 目标 100 MHz，与 AXI DMA/PS 互联时钟配合。

**存储资源规划：**

- BRAM：5×5 形态学行缓冲和数据流 FIFO，HLS 估算使用 26 个 BRAM_18K。
- DDR：PS 端输入、输出帧缓冲以及界面图像。

## 4. LLM 辅助优化记录

### 4.1 设计阶段LLM辅助

#### 4.1.1 架构设计咨询

**优化目标：** 在不破坏已有静态识别的前提下确定 PS/PL 分工。

**用户输入摘要：** 希望使用 PYNQ-Z2 实现手语动作识别、文字显示与语音播报，并把适合的图像处理放入 PL。

**LLM回答摘要：** 建议将规则固定、逐像素的 YCrCb 分割和形态学放入 PL，将摄像头、轮廓、模板分类、UI 和语音保留在 PS；动态手势应采用独立入口，验证稳定后再合并。

**采用建议：** 实际采用 AXI DMA + HLS `skin_morph` + PS 模板分类架构，并将未稳定的动态链路与正式静态入口隔离。

#### 4.1.2 状态流程优化

**优化目标：** 避免 DMA 卡死、重复播报和停止后资源未释放。

**优化实施：** 明确初始化、采集、PL 处理、分类、稳定确认、显示与停止阶段；DMA 接收先于发送，增加超时；通过稳定计数与释放条件抑制重复语音。

### 4.2 实现阶段LLM辅助

#### 4.2.1 代码优化

**优化目标：** 降低 Notebook 产品页面卡顿。

**分析与改进：** 分阶段计时发现分类约 0.02 ms，而原始大图合成/JPEG 约 462.78 ms，瓶颈主要在显示而非分类。系统随后降低页面刷新率、直接按目标尺寸绘制并调整 JPEG 质量，探索性显示编码时间降至约 87.78 ms。

#### 4.2.2 图像链路优化

**优化目标：** 解决空背景误检。

**分析与改进：** 完整灰世界白平衡会放大暗背景色偏，使其进入肤色阈值。板上 A/B 测试后改为强度 0.2 的受限白平衡，使背景稳定，同时保留一定颜色校正能力。

### 4.3 调试阶段LLM辅助

#### 4.3.1 板级问题解决

**问题描述：** 初期出现摄像头管线警告、页面卡顿、语音未触发和动态类别混淆。

**问题解决：** 区分 GStreamer 尝试警告与实际 USB 摄像头链路；定位显示瓶颈；修复浏览器 WAV 触发链路；动态模型现场未稳定，因此不纳入正式成果，保护已验证静态链路。

### 4.4 LLM辅助总结

**效果评估：**

- 设计效率：快速形成 PS/PL 分工、DMA 排查顺序和分层验证清单。
- 代码质量：增加超时、资源释放、稳定确认和部署隔离，减少演示风险。
- 学习效果：掌握用测量证据区分 PL、摄像头、分类与 UI 瓶颈的方法。

**使用心得：** 精确描述硬件版本、现象和完整日志比泛化提问更有效；LLM 擅长结构化分析和生成检查步骤，但资源、时序、准确率与硬件状态必须由真实报告或板上结果确认。

## 7. 创新点与特色

### 7.1 设计创新点

1. **逻辑设计创新：** 使用定点 YCrCb 与四级 5×5 形态学流水完成可解释的硬件手部分割。
2. **状态流程创新：** 把 DMA 超时、稳定确认、语音去重和安全停止纳入完整产品控制流程。
3. **时序设计创新：** 通过 PIPELINE、DATAFLOW 和行缓冲实现目标 II=1，避免多幅中间帧占用。
4. **接口设计创新：** 以 AXI4-Stream、AXI4-Lite 和 AXI DMA 构成参数可调、软硬件解耦的处理链路。

### 7.2 工程实现特色

系统不是只输出类别，而是同步显示真实画面、PL mask、识别文字和离线语音；板端使用独立 `sign_demo_v2` 目录，避免破坏原工程；动态实验与正式静态入口隔离，提高现场演示可靠性。

### 7.3 LLM辅助方法创新

采用“提出建议—分阶段测量—板上确认—不通过则回退”的闭环使用 LLM，并将 bit/hwh 配对、DMA 顺序、mask 极性和性能分段计时沉淀为可复用验证 Skill。

## 8. 未来改进方向

### 8.1 当前不足

- 静态类别数量有限，未知动作拒识能力仍需独立数据集验证。
- 尚未取得完整 Vivado post-route 资源、时序和功耗报告。
- 产品页未记录正式端到端 FPS、P50/P95 延迟。
- 动态手势模型现场稳定性不足，未纳入最终演示。

### 8.2 改进计划

- 建立每类至少 20 次和未知动作至少 50 次的独立测试集，输出混淆矩阵。
- 对同一批图像执行 CPU/PL mask IoU 与预处理延迟对比，预热后测试至少 1000 帧。
- 导出最终 Vivado utilization、timing summary 和 power 报告。
- 在不影响静态链路的独立分支中训练和验证动态时序模型。

### 8.3 后续发展方向

可增加双手动作、动态词汇和语句拼接，加入音量/语言配置，并评估把连通域或特征累积进一步下放 PL 的收益。

### 11.2 关键LLM交互记录

**重要交互1：PS/PL 架构划分**

- 用户问题：怎样在 PYNQ-Z2 上实现手语识别和语音，并让 PL 承担更多加速。
- LLM建议：PL 负责规则化像素处理，PS 负责轮廓、分类、UI 和语音。
- 实施效果：最终页面明确显示 `PL SEGMENTATION / ARM PS`，板上链路通过。

**重要交互2：卡顿定位**

- 用户问题：为什么 PL 已启用但界面仍延迟、卡顿。
- LLM建议：分别测量摄像头、DMA/PL、分类和 JPEG/显示，不凭感觉归因。
- 实施效果：定位主要瓶颈为大图合成/JPEG，将探索性显示处理由约 462.78 ms 降至约 87.78 ms。

**重要交互3：白平衡和背景误检**

- 用户问题：希望白平衡不要完全关闭，同时保持识别稳定。
- LLM建议：采用强度可调的部分白平衡，并用空背景 mask 进行 A/B 验证。
- 实施效果：最终使用强度 0.2，空背景误检得到控制，正式静态演示稳定。
