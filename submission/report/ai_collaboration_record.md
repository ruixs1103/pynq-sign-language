# 大模型协作记录

## 1. 使用原则

大模型用于辅助设计评审、代码整理、错误定位、测试设计与文档生成。模型输出不直接作为硬件正确性证据；bitstream、资源、时序、性能和准确率必须由工具报告或真实板卡验证。

## 2. 主要协作阶段

| 阶段 | 人类目标 | 模型辅助 | 人类验证/纠错 |
|---|---|---|---|
| 路线整合 | 以参考项目为主合并当前工程 | 对比两条技术路线并非破坏性合并 | 保留旧路线作回退，参考路线同名文件优先 |
| 板端部署 | 不覆盖板端原项目 | 建议建立 `sign_demo_v2` 并逐步上传 | 实际通过 SSH/Jupyter 验证目录隔离 |
| PL 验证 | 确认 Overlay/DMA 工作 | 给出加载、一帧分割和分类检查步骤 | IP 列表和 PL mask 在板上通过 |
| 背景误检 | 空背景被识别成手 | 定位为完整灰世界白平衡导致阈值漂移 | 关闭后空背景 mask 比例 0；采用强度 0.2 |
| 卡顿定位 | Notebook 画面延迟大 | 分阶段计时，识别显示瓶颈 | JPEG/合成约 462.78 ms，轻量显示约 87.78 ms |
| 产品化 | 独立静态演示与语音 | 生成低延迟入口、WAV 播放、Voilà 页面 | 数字显示和播报在板上正常 |
| 动态实验 | 尝试加入动态手势 | 采用独立入口保护静态链路 | 现场混淆，决定暂不纳入正式产品 |

## 4. 关键自我纠错轨迹

1. 初始大尺寸展示被怀疑是 PL 性能不足。分阶段基准表明分类仅约 0.02 ms，而显示/JPEG 占主要耗时，因此没有盲目继续扩大 PL。
2. 完整白平衡在暗背景下造成大块前景。通过空背景 A/B 测试确认后，改为可调且有界的 0.2 强度。
3. 动态模型虽有离线准确率，但现场把“你好”混淆为“帮助”。因此保持动态入口隔离，不把未经验证的功能写成完成。
4. 为保护板端原项目，所有新文件部署到 `sign_demo_v2`，未覆盖 `sign_demo`。

## 5. Skill 提炼过程

从本项目中抽取的通用经验包括 bit/hwh 配对、Overlay IP 检查、AXI-Lite 寄存器映射、DMA 顺序、mask 极性、CPU/PL 对比、分阶段计时和停止条件。Skill 明确不绑定手语类别、摄像头型号或本项目目录。
